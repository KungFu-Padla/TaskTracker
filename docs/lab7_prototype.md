# Лабораторная работа № 7. Прототип в IDE, тесты и GitHub Actions

**Цель:** сделать прототип (минималистический) проекта в используемой IDE, вести разработку через GitHub, написать 1–2 простейших теста для проекта и «прошить» их в GitHub Actions в автоматическом режиме.

## Инструменты
- IDE: VS Code / PyCharm / любая другая
- Язык: Python + Flask
- Система контроля версий: Git + GitHub
- Тесты: pytest
- CI: GitHub Actions (`.github/workflows/ci.yml`)

## Шаг 1. Прототип проекта (app.py)
Создан минималистический веб-прототип TaskTracker:
- `GET /tasks` — список задач;
- `POST /tasks` — создание задачи;
- `POST /tasks/<id>/complete` — отметка выполнения;
- `DELETE /tasks/<id>` — удаление задачи;
- `GET /health` — проверка работоспособности.

Запуск:
```
python app.py
```
Приложение доступно по http://127.0.0.1:5000

## Шаг 2. Тесты проекта (1–2 штуки)
В `tests/test_app.py` реализованы 2 теста:
- `test_create_task` — создание задачи через тестовый клиент Flask (ожидается 201 и поля `id`, `title`, `done`).
- `test_complete_task` — пометка задачи выполненной (поле `done` становится `True`).

Запуск локально:
```
pytest
```

## Шаг 3. Интеграция с GitHub Actions
Файл `.github/workflows/ci.yml` запускает `pytest` при каждом `push` в `main`/`develop` и при каждом `pull_request`.Таким образом тесты «прошиты» в автоматическом режиме — при каждом изменении кода на GitHub проверяется, что прототип работает корректно.

## Шаг 4. Ведение через GitHub
- Весь код ведётся в репозитории GitHub (см. ЛР 2).
- Ветка `develop` — для разработки прототипа, `main` — стабильная версия.
- Перед слиянием в `main` создаётся Pull Request, прогоняется CI (тесты).

## Итоговые артефакты
- `app.py` — прототип приложения.
- `tests/test_app.py` — 2 теста проекта.
- `.github/workflows/ci.yml` — автоматический прогон тестов.
- Успешный запуск воркфлоу на GitHub (скриншот в отчёт).
- Ссылка на репозиторий в отчёте.
